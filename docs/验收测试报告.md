### 3.3 频率限制实测与应对（本次最重要的一次真实踩坑）

采集密度升高后，`/car-detail/*.md` 通道开始**以 HTTP 200 返回站点的 SPA 空壳页**
（不是 403、不是验证码，就是一个正常状态的空壳）。

| 观测 | 推断 |
|---|---|
| 空壳页 `text/html`、长度恒定、所有 URL 返回同一份 | 通道级风控，不是单条数据问题 |
| 站点地图 `*.xml` 始终正常，仅内容通道受限 | 限制作用在**内容路径**而非整站 |
| 换 UA（含 robots 白名单里的 AI 爬虫）结果不变 | 非 UA 判定 |
| 换真实浏览器指纹（Playwright + 完整浏览器环境）结果不变 | 非指纹判定 |
| 直连与本机代理出口均被拦 | 属**出口 IP 级**软封禁 |

**已落地的应对**：

1. **内容契约校验**（`looks_like_detail_md`）：空壳页判为"被拦截"，绝不静默计入缺失率；
2. **冷却 + 熔断**：命中风控即等待（默认 150s，可调），达到上限收手，不硬刚；
3. **断点续爬**：每条成功即写 `data/checkpoints/*.urls`，中断不丢进度；
4. **raw 层回放**（`replay`）：把"取数"与"解析"解耦，取数受限时仍能完成入库与看板。

> **交付说明**：本报告的 103 条数据来自真实抓取的原始响应；在出口 IP 未被限流的
> 环境下，`crawl` 命令可直接实时抓取，两条路径产出完全同构。

## 七、问题清单与处置

### P0：详情页通道被 IP 级软风控（**已缓解，非代码缺陷**）

- **现象**：`/car-detail/*.md` 在请求密度升高后返回 HTTP 200 空壳页。
- **根因**：站点侧对出口 IP 的软封禁（已排除 UA / 指纹 / URL 形态因素）。
- **处置**：内容契约校验 + 冷却熔断 + 断点续爬 + raw 层回放（详见 §3.3）。
- **根治方案**：接入代理池（已在 `fetcher` 预留出口配置点），列为 P0 迭代项。

### P1：续航前缀语序丢失（**已修复**）

- **现象**：源站文案混用 `续航605公里` 与 `610km续航` 两种语序，只认后缀式时
  23 条含续航描述的 EV 里仅抽出 6 条。
- **修复**：新增前缀式正则，抽取数从 6 提升到 **18**；其余 5 条经核查为
  车型名（"长续航版"）或增程车综合续航，**属于应当丢弃的情况**。
- **回归**：新增 4 个测试用例锁定。

### P1：详情页源与列表页源会被静默跳过（**已修正**）

- **现象**：`crawl` 只处理"站点地图型"源，列表页型源被静默忽略，易造成"配了却没跑"。
- **处置**：显式打印被跳过的源并提示改用 `run` 命令。

### P2：`CrawlLog` 模型不接受 `replay` 任务类型（**已修复**）

- **现象**：回放入库时报 `ValidationError: task_type`。
- **处置**：`TaskType` 字面量增加 `replay`。

### P3：`detail_runner` 引用了未导入的 `PROJECT_ROOT`（**已修复**）

- **现象**：`crawl` 在断点续爬阶段抛 `NameError`，整批采集中断。
- **处置**：补齐 `from ..config import PROJECT_ROOT` 与 `pathlib.Path` 导入。
