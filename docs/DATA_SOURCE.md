## 二、瓜子的 robots.txt 原文（2026-09-19 实测）

```
User-agent: *
# 允许抓取所有核心内容
Allow: /
Allow: /llms.txt
Allow: /llms-full.txt
Allow: /car-detail/*.md
Allow: /*.md$

Disallow: /*?*

Sitemap: https://www.guazi.com/guazisou/cardetail/pc_cardetail_md_index.xml
```

### 关键解读

1. **`Allow: /car-detail/*.md` 与 `Allow: /*.md$`** —— 平台**主动**把车源详情页的 Markdown 版本、
   连同 `llms.txt` / `llms-full.txt` 一起放行，属于面向机器读取发布的内容。
   配套的站点地图 `pc_cardetail_md_index.xml` 把这些页面编入索引，`lastmod` 每日更新。
2. **`Disallow: /*?*`** —— 禁止一切带查询参数的 URL。
   本采集器的所有 URL 都是**路径式**的（`/car-detail/c123456.md`、`/guazisou/.../pc_cardetail_md_1.xml`），
   **不含任何 `?`**。这一点在配置层做了硬校验（`allow_query_params: false`），
   一旦有人在 `url_template` 里写了 `?`，**配置加载就会直接失败**，而不是跑到线上才发现。
3. **`Disallow: /` 对懂车帝 / 汽车之家的处置** —— 两个源在 `sites.yaml` 中保留配置但
   `enabled: false` + `robots_status: disallowed`，运行时的 `RobotsGate` 仍会在每次请求前实时复核，
   并且 `_compliance_guard` 会在发请求**之前**就拦下。保留它们是为了让"为什么不抓"这件事可审计，
   而不是删掉了事。

## 三、为什么只选 Markdown 通道

| 通道 | robots 状态 | 反爬强度 | 字段完整度 | 结论 |
|---|---|---|---|---|
| `/car-detail/*.md` | **显式 Allow** | 低（文本文件） | 高（结构化键值 + 车况档案） | ✅ **采用** |
| HTML 列表页 `/bj/buy/o2/` | Allow | 高（需隐身/浏览器档） | 低（只有卡片上的少量字段） | ⏸️ 暂不用 |
| HTML 详情页 `/car-detail/*.html` | Allow（但未显式放行） | 高 | 高 | ❌ 不需用 |

工程判断：**同样的信息，Markdown 通道的成本、稳定性、字段质量全面占优**——
它本来就是平台为机器读取准备的结构化内容。这是"能拿简单通道就不啃硬通道"的典型取舍。

## 四、实测到的反爬机制与应对（诚实记录）

这条通道也**不是完全无限制**的。实测结论如下：

| 现象 | 观察 |
|---|---|
| 站点地图 `/guazisou/**/pc_cardetail_md_*.xml` | **可以持续拉取**，单文件约 1.2 MB / 1 万条 URL，无明显限制 |
| 详情页 `/car-detail/*.md` | 短时间请求过多后**被挑战**：返回 HTTP **200**，但内容是 `uc.guazi.com/.../captcha` 的验证页（约 4 KB 的 JS 空壳） |
| 挑战持续时间 | 实测 ≥ 12 分钟仍处于挑战状态；因此冷却时间设为 **150 秒**不足以立刻恢复，需靠**降低速率 + 断点续爬跨任务累积** |
| 影响范围 | **路径级**，不是 IP 全站封锁：同一时刻站点地图仍可正常访问 |

### 本项目的应对（均已在代码中落地）

1. **内容契约校验**：HTTP 200 ≠ 拿到数据。每一份响应都必须以 `---` 开头、且含 `vehicle_core` / `full_payment`，
   否则判定为挑战页。**绝不把验证页当成"解析不到字段的合法页面"混进统计**——
   这是爬虫项目最常见的数据质量事故（成功率虚高、缺失率失真）。
2. **令牌桶限速**：单站 QPS ≤ 0.2（5 秒/请求）。
3. **冷却 + 熔断**：命中挑战 → 冷却 150 秒后重试同一 URL；连续 4 次仍被拦 → **熔断收手**，
   把本次任务标记为 `partial` 并告警，而不是继续硬刚把通道打死。
4. **断点续爬**：每成功一条就写 checkpoint，被限流打断后重跑会跳过已完成部分，
   已消耗的请求不会白费。长时间采集可以分多次增量完成。
5. **不绕过验证码**：面对挑战页，项目**只做降速与等待**。不接入打码、不破解验证码、不伪造登录态。
   这是合规红线，也是本项目的明确立场。

> 面试话术锚点："这条通道是平台自己在 robots.txt 里放行、并编入站点地图的，
> 我按它给的节奏走。它有限速我就限速，它出验证页我就退让——
> 爬虫工程师的价值不是突破封锁，而是**长期、稳定、合规地拿到干净数据**。"

## 五、仍然遵循的通用约束

- **只采公开信息**：不登录、不付费、不访问任何需要授权的页面；
- **不采集个人隐私**：车源详情里不含卖家个人信息；本项目的字段表（见 `data-dictionary.md`）
  也**不包含**任何可定位到自然人的字段；
- **低频采集**：QPS ≤ 0.2，夜间低峰运行（调度默认 02:30 / 02:50）；
- **可溯源**：每一条数据都在 `raw_ref` 里留下了原始响应的落盘路径（gzip 快照 + 元数据），
  任何统计结论都能回溯到当时的原文；
- **数据用途**：仅用于个人学习与求职作品展示，不用于任何商业用途。

## 六、复核方式

```bash
# 打印各源的 robots 档案（离线，读配置）
python -m usedcar_crawler compliance

# 联网实时复核 robots.txt（只请求 robots.txt 本身，不抓任何内容页）
python -m usedcar_crawler compliance --verify
```

**建议复核频率**：每月一次，或每次站点改版/大量抓取失败后立即复核。
`config/sites.yaml` 中每个源都带 `compliance.checked_at` 与 `note`，
复核后请同步更新这两个字段——让"上次什么时候确认过"永远可查。
